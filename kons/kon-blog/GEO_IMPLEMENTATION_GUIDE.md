## 1. Database Modeling

### The fields

These columns of `blog_posts` hold the GEO and SEO data (Drizzle: `src/schema.local.ts`; SQL:
`migrations/0000_initial.sql` and later files):

```typescript
interface BlogPost {
  // Standard fields
  id: string;
  title: string;
  slug: string;
  content: unknown; // jsonb: an HTML string or a JSON document
  excerpt: string | null;

  // GEO (Generative Engine Optimization)
  /** Bottom Line Up Front: a summary of at most 50 words (column bluf_text) */
  blufText: string | null;
  /** FAQ: [{ "q": "Question", "a": "HTML answer", "order": 1 }] (column faq_data, jsonb) */
  faqData: FAQItem[] | null;
  /** URL of the source dataset, for articles based on data (column dataset_url) */
  datasetUrl: string | null;

  // SEO
  metaTitle: string | null; // varchar(70)
  metaDescription: string | null; // varchar(170)
  ogImageId: string | null; // uuid of a media item; the OG image URL is built from it
  featuredImageId: string | null; // uuid of a media item
  featuredImageFocalPoint: { x: number; y: number } | null; // 0-1, for cropping
  seoOverrides: Record<string, unknown> | null;

  status: "draft" | "published" | "scheduled" | "archived";
  publishedAt: Date | null;
  authorId: string;
  readingTime: number | null; // minutes, set by the editor
}
```

There is no column for an OG image URL or its size: the image is a media item (`ogImageId`, or
`featuredImageId` when there is no OG image) and its URL is generated by `getOGImageUrl()`
(`/api/media/transform/<id>?w=1200&h=630&fit=cover&f=jpeg&q=90`, see `src/seo-utils.ts`).

Full-text search uses a `search_vector` column (English configuration, over title, excerpt and
content) kept by a trigger (`migrations/0009_final_shape.sql`). There is no separate index on the
BLUF.

### BLUF Validation (Strict)

```typescript
import { validateBLUF } from "./geo-utils";

// What create-post (POST /api/blog) does when blufText is sent
const blufValidation = validateBLUF(body.blufText);

if (!blufValidation.isValid) {
  return c.json(
    {
      error: "Validation failed",
      field: "blufText",
      message: "BLUF validation failed",
      details: blufValidation.errors, // blocking errors
      warnings: blufValidation.warnings,
      metrics: blufValidation.metrics, // { wordCount, charCount, readingTime }
    },
    400
  );
}

// Errors (block the save):
// - empty BLUF
// - more than 50 words
// Warnings (do not block):
// - more than 40 words, or fewer than 10
// - more than 70% capital letters
// - does not start with a capital letter
// - does not end with . ! or ?
```

### HTML Sanitization

```typescript
import { sanitizeHTML, sanitizeFAQText, ALLOWED_HTML_TAGS } from "./geo-utils";

// For FAQs: allow only basic formatting
const cleanFAQ = sanitizeFAQText("<p>Answer</p><script>alert('xss')</script>");
// Result: "<p>Answer</p>"

// For general content: allow tables and structure
const cleanContent = sanitizeHTML(htmlContent, {
  allowedTags: ALLOWED_HTML_TAGS,
});

// ALLOWED_HTML_TAGS:
// - Text: p, br, hr, strong, b, em, i, u, mark, small, del, ins, sup, sub
// - Lists: ul, ol, li
// - Tables: table, thead, tbody, tr, th, td, caption
// - Headings: h3, h4
// - Links: a (href limited to http, https, mailto, tel)
// - Others: blockquote, code, pre
// FAQ answers (sanitizeFAQText) allow only p, br, strong, b, em, i, a, code.
//
// The post body itself (`content` as HTML, and markdown in blocks) is sanitized by
// src/sanitize.ts on write and on read, not by sanitizeHTML.
```

## 3. API Payload

### Endpoint: `GET /api/blog/geo/:slug`

Returns structured JSON for the frontend. Optional query: `siteName` (default `Kitsuden CMS`) and
`baseUrl` (default: the API's own origin), used for the title suffix and the canonical URL. A post
that is not published (or whose `publishedAt` is in the future) is a `404` for the public; staff
can read it with `?preview=true`.

### Frontend Usage (Astro)

```astro
---
// src/pages/blog/[slug].astro
const { slug } = Astro.params;
const response = await fetch(`https://api.example.com/api/blog/geo/${slug}`);
const { data } = await response.json();
---

<html>
  <head>
    <!-- SEO Meta Tags -->
    <title>{data.seo.title}</title>
    <meta name="description" content={data.seo.description} />
    <link rel="canonical" href={data.seo.canonicalUrl} />

    <!-- Open Graph -->
    <meta property="og:title" content={data.seo.title} />
    <meta property="og:description" content={data.seo.description} />
    <meta property="og:image" content={data.seo.ogImage} />

    <!-- FAQ Schema -->
    {data.geo_ai.schema_faq && (
      <script type="application/ld+json">
        {JSON.stringify(data.geo_ai.schema_faq)}
      </script>
    )}

    <!-- Article Schema with BLUF -->
    <script type="application/ld+json">
      {JSON.stringify({
        "@context": "https://schema.org",
        "@type": "BlogPosting",
        headline: data.seo.title,
        description: data.seo.description,
        abstract: data.geo_ai.bluf,  // BLUF as abstract
        datePublished: data.publishedAt
      })}
    </script>
  </head>

  <body>
    <!-- BLUF - Visible to users and extractable by AI -->
    <div class="bluf-box">
      <strong>Summary:</strong> {data.geo_ai.bluf}
    </div>

    <!-- Table of Contents -->
    <nav class="toc">
      <h2>Contents</h2>
      <ul>
        {data.content.toc.map(item => (
          <li class={`toc-level-${item.level}`}>
            <a href={`#${item.id}`}>{item.text}</a>
          </li>
        ))}
      </ul>
    </nav>

    <!-- Main Content (when the body is stored as HTML; a JSON document needs rendering) -->
    <article set:html={data.content.body} />

    <!-- FAQs -->
    {data.geo_ai.schema_faq && (
      <section class="faqs">
        <h2>Frequently Asked Questions</h2>
        {data.geo_ai.schema_faq.mainEntity.map((faq, i) => (
          <details class="faq-item">
            <summary>{faq.name}</summary>
            <div set:html={faq.acceptedAnswer.text} />
          </details>
        ))}
      </section>
    )}
  </body>
</html>
```

### Recommended Components

#### 1. BLUF Editor with Counter

```svelte
<!-- BLUFEditor.svelte -->
<script>
  let value = $state("");
  let maxWords = 50;

  const wordCount = $derived(
    value
      .trim()
      .split(/\s+/)
      .filter((w) => w).length
  );
  const isValid = $derived(wordCount <= maxWords && wordCount >= 10);

  const validation = $derived(validateBLUF(value));
</script>

<div class="bluf-editor">
  <label>
    BLUF (Bottom Line Up Front)
    <span class="hint">{maxWords}-word summary for AI</span>
  </label>

  <textarea
    bind:value
    rows="3"
    placeholder="Write a concise summary that answers the article's main question..."
    class:invalid={!validation.isValid}
  />

  <div class="bluf-stats" class:warning={wordCount > 40} class:error={wordCount > 50}>
    <span>{wordCount}/{maxWords} words</span>
    <span>•</span>
    <span>~{Math.ceil(wordCount / 3)} sec read</span>

    {#if validation.warnings.length > 0}
      <span>•</span>
      <span class="warning-text">⚠️ {validation.warnings[0]}</span>
    {/if}
  </div>

  {#if validation.errors.length > 0}
    <div class="bluf-errors">
      {#each validation.errors as error}
        <div class="error-text">❌ {error}</div>
      {/each}
    </div>
  {/if}
</div>
```

#### 2. FAQ Repeater

```svelte
<!-- FAQRepeater.svelte -->
<script>
  let faqs = $state([{ q: "", a: "", order: 0 }]);

  function addFAQ() {
    faqs.push({ q: "", a: "", order: faqs.length });
  }

  function removeFAQ(index) {
    faqs.splice(index, 1);
  }

  function moveFAQ(index, direction) {
    const newIndex = index + direction;
    if (newIndex >= 0 && newIndex < faqs.length) {
      [faqs[index], faqs[newIndex]] = [faqs[newIndex], faqs[index]];
    }
  }
</script>

<div class="faq-repeater">
  <label>Frequently Asked Questions</label>
  <p class="hint">Add FAQs for Google rich snippets</p>

  {#each faqs as faq, i}
    <div class="faq-item">
      <div class="faq-header">
        <span class="faq-number">#{i + 1}</span>
        <div class="faq-actions">
          <button onclick={() => moveFAQ(i, -1)} disabled={i === 0}>↑</button>
          <button onclick={() => moveFAQ(i, 1)} disabled={i === faqs.length - 1}>↓</button>
          <button onclick={() => removeFAQ(i)} class="danger">✕</button>
        </div>
      </div>

      <input bind:value={faq.q} placeholder="Question" class="faq-question" />

      <textarea
        bind:value={faq.a}
        placeholder="Answer (limited HTML allowed)"
        rows="3"
        class="faq-answer"
      />

      <div class="faq-toolbar">
        <button type="button" onclick={() => insertTag(i, "strong")}>
          <strong>B</strong>
        </button>
        <button type="button" onclick={() => insertTag(i, "a")}> 🔗 Link </button>
        <button type="button" onclick={() => insertTag(i, "code")}> &lt;/&gt; Code </button>
```

#### 3. Block editor — decision: own format, NOT Lexical

> **Decided 2026-08-01.** This section used to describe Lexical (Meta's editor, the
> same one Ghost's Koenig uses). It is **not adopted**, and the code never had it
> installed — the schema comment that said "Lexical rich text JSON" was
> wrong and has already been corrected.

**Why not Lexical.** Its core is agnostic, but the plugin ecosystem
—which is where the real value lies— is _React-first_. Adopting it in a Svelte admin
means writing the bindings for each plugin yourself, and that is a permanent
cost, not a one-off.

**What is there instead.** An own block editor, already written and with no
external editor dependency:

- `packages/admin/src/lib/components/editor/SlashCommandEditor.svelte`
- `packages/admin/src/lib/components/builder/BlockEditor.svelte`

It supports headings, image, quote, code, divider and button via slash commands.

**If someday more is needed than what the own editor gives**, the alternative is
**TipTap** (on top of ProseMirror), which does have official Svelte support. Lexical
only if someone agrees to maintain the bindings.

**What must be got right first**, and in this order:

1. **Formalize the document schema** with Zod and **version it**. It is the critical
   piece: migrating already published content hurts far more than changing the editor,
   which is replaceable.
2. **Server-side renderer** (JSON → HTML). It is needed anyway for SEO,
   RSS and to avoid depending on the client when rendering an article.
3. **Afterwards**, editor polish: drag reordering, markdown shortcuts
   (`## ` → h2), embeds with unfurl, image with caption.

Kitsuden's differentiator versus Ghost is not the editor UX —there Ghost
has years of advantage— but the GEO fields (`blufText`, `faqData`, `datasetUrl`)
that make content readable to AI search engines. Chasing Koenig head-on is a sink; the
document format is not.

## 5. Usage Examples

### Create a Post with Full GEO

```bash
POST /api/blog
Content-Type: application/json

{
  "title": "SEO Guide 2024: Optimizing for AI",
  "slug": "seo-guide-2024-ai",
  "blufText": "SEO in 2024 requires quality content, an excellent user experience and optimization for voice search.",
  "faqData": [
    {
      "q": "What is SEO in 2024?",
      "a": "SEO in 2024 focuses on <strong>helpful content</strong> written by humans..."
    },
    {
      "q": "How does AI affect SEO?",
      "a": "AI is changing how Google evaluates content..."
    }
  ],
  "datasetUrl": "https://example.com/datasets/seo-survey-2024.csv",
  "metaTitle": "SEO Guide 2024 | My Blog",
  "metaDescription": "Learn the best SEO techniques for 2024",
  "ogImageId": "<uuid of a media item>",
  "content": "<h2>Introduction</h2><p>SEO has evolved...</p>",
  "status": "published"
}
```

`create-post` needs a staff session (or an agent key with `kon:blog:create-post` and an
`authorId`). With `status: "published"` the post is published at once.

### Consumption in React

```tsx
// components/BlogPost.tsx
import { useEffect, useState } from "react";

interface BlogPostData {
  seo: { title: string; description: string; ogImage: string };
  geo_ai: { bluf: string; schema_faq: any; reading_time: number };
  content: { body: any; toc: any[] };
}

export default function BlogPost({ slug }: { slug: string }) {
  const [data, setData] = useState<BlogPostData | null>(null);

  useEffect(() => {
    fetch(`/api/blog/geo/${slug}`)
      .then((r) => r.json())
      .then(({ data }) => setData(data));
  }, [slug]);

  if (!data) return <div>Loading...</div>;

  return (
    <article>
      <Head>
        <title>{data.seo.title}</title>
        <meta name="description" content={data.seo.description} />
        <script
          type="application/ld+json"
          dangerouslySetInnerHTML={{
            __html: JSON.stringify(data.geo_ai.schema_faq),
          }}
        />
      </Head>

      <div className="bluf-box">
        <strong>TL;DR:</strong> {data.geo_ai.bluf}
        <span className="reading-time">⏱️ {data.geo_ai.reading_time} min read</span>
      </div>

      <nav className="toc">
        {data.content.toc.map((item) => (
          <a key={item.id} href={`#${item.id}`} className={`level-${item.level}`}>
            {item.text}
          </a>
        ))}
      </nav>

      <div dangerouslySetInnerHTML={{ __html: data.content.body }} />
    </article>
  );
}
```
