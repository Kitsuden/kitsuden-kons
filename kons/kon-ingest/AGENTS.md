# AGENTS.md — kon-ingest

Notes for AI agents: coding agents changing this kon, and agents that call it through Kitsuden.
Repository-wide rules: [../../AGENTS.md](../../AGENTS.md).

## What it is

Document ingestion at `/api/ingest`: store a document, extract its text on the Postgres queue, cut it into
chunks and embed them for semantic search. Built from the core's `modelOperations`: two models (`document`, `chunk`)
generate most operations; `ingest-document` is the kon's own.

## Calling it

- Scopes. Ingest: `document:write`. Poll and list documents: `document:read`. Search and read chunks:
  `chunk:read`. Fine scopes also work (`kon:ingest:ingest-document`, `kon:ingest:search-chunks`), and
  `ingest:*` opens the whole kon. Example key: `["document:write", "document:read", "chunk:read"]`.
- The usual flow over MCP: `ingest__ingest-document` (body `{ title, mimeType, content }` or
  `contentBase64` for PDF and images) returns `{ id, status: "pending" }`; poll `ingest__get-document`
  (`id`) until `status` is `done` or `failed` (then read `error`); then `ingest__search-chunks`
  (`q`, `limit`) returns `{ data: [{ ...chunk, score }] }`.
- Prefer the ingest operation, which checks `content` / `contentBase64` and answers 202. `create-document`
  also queues the processing job.
- `delete-document` and `delete-chunk` are sensitive: with human approval on they return
  `202 KITSUDEN_E_APPROVAL_REQUIRED`. Report the proposal; do not retry. Deleting a document deletes its
  chunks in the same transaction.
- A 404 means the row does not exist or belongs to someone else; the API never says which. An agent owns
  what it ingests (its identity is `owner_id`); without `ingest:*` it sees only its own rows.
- `ingest-document` is not idempotent: each call stores and processes a new document. Pass
  `idempotency_key` (MCP) or `Idempotency-Key` (REST) if you may retry.
- `search-chunks` answers 503 when the server has no embeddings provider. Chunks of a document that just
  finished may not be searchable for a moment: embeddings are computed in the background.
- Refused: both or neither of `content` and `contentBase64` (422); `content` over 7 MB; unsupported types
  end `failed` rather than erroring at upload.

## Rules that must hold

- The job is queued in the same transaction as the document insert, by `ingest-document` and by
  `create-document` (`index.ts`; `tests/unit/kon-ingest.test.ts`, "queues the job in the same request",
  "a document created with create-document is queued").
- Deleting a document deletes its chunks in the same transaction (trigger in
  `migrations/0003_delete_chunks_with_document.sql`; test "deleting a document deletes its chunks").
- The job is idempotent: it deletes the document's chunks before inserting them again (`job.ts`; test
  "is idempotent").
- An unreadable document ends `failed` and the job returns without throwing; transient failures throw so the
  queue retries (`job.ts`; tests on `CannotExtract` and the sidecar).
- Every chunk keeps its document's `owner_id` (`job.ts`; test "keeps the owner on every chunk").
- Row security keeps each user's rows apart in the database, not only in the route filter (test "the
  database itself keeps the rows apart").
- Agents get in only through scopes; the model policy returns false for agents.
- PDF and OCR never run inside the API process beyond the optional `unpdf` import; OCR is a sidecar.

## Changing it

- Models: edit `ingest.model.ts`, then `kitsuden makemigrations --kon ingest` to write the next migration
  and update `migrations/models.snapshot.json`. Review the generated SQL.
- New migration by hand: next number in `migrations/` (`0004_...sql`). Never edit an applied one; old
  checksums go in `migrations/history.json`.
- Changing the embedding size: `semantics.dimensions` in `ingest.model.ts` and the `dimensions` in `job.ts`
  must match, plus a migration for the column.
- New file at the root: run `pnpm kon:sync` (it updates `package.json` `files` and `kon.json`).
- Bump `version` in `package.json` and run `pnpm kon:sync`, which copies it to `kon.json`, for a behaviour change.
  `index.ts` reads the version from `kon.json`.
- `extract.ts` is imported by kon-chat (`../kon-ingest/extract`): keep `extractText(mime, content)` stable.
