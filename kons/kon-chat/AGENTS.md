# AGENTS.md — kon-chat

Notes for AI agents: coding agents changing this kon, and agents that call it through Kitsuden.
Repository-wide rules: [../../AGENTS.md](../../AGENTS.md).

## What it is

Chatbots over the core's agent identities, mounted at `/api/chat`. Team bots (admins and editors, optionally
only named members) may use one tool group; public bots answer anyone on a website from taught knowledge
only, never with tools. The kon stores bots, knowledge chunks, conversations and messages.

## Calling it

- Agents manage bots; they do not chat with them over MCP. The 11 MCP tools are the configuration and
  oversight operations (`chat__list-chatbots`, `chat__create-chatbot`, `chat__update-chatbot`,
  `chat__delete-chatbot`, `chat__list-chatbot-knowledge`, `chat__add-chatbot-knowledge`,
  `chat__delete-chatbot-knowledge`, `chat__list-chatbot-conversations`, `chat__get-chatbot-usage`,
  `chat__list-chatbot-feedback`, `chat__get-chat-conversation`). Each returns `{ data: ... }`.
- Scopes: the kon-wide `chat:*` (or `kon:chat:*`) for everything, the policy scope `chat:configure` for
  every admin operation, or one operation's fine scope (`kon:chat:list-chatbots`). The route and the tables'
  row security accept the same scopes (`migrations/0002_fine_scopes_in_rls.sql`). `get-chat-conversation`
  shows only the caller's own conversations unless the key opens the whole kon. A denial
  (`!kon:chat:delete-chatbot`, `!chat:*`) beats everything, `admin` included.
- Sensitive operations (create, update, delete, add knowledge, delete knowledge) may come back
  `202 KITSUDEN_E_APPROVAL_REQUIRED` when human approval is on. Report the proposal; do not retry.
- 404 means missing, or not yours: a conversation of someone else, a team bot whose `members` exclude the
  caller, an inactive bot, or a bot of the other audience. The API never says which.
- Writes are POST/PATCH/DELETE without natural idempotency except DELETE; pass `idempotency_key` (MCP) or
  `Idempotency-Key` (REST) on create or add-knowledge if you may retry.
- Refused on purpose: a public bot with `toolset` or `members` (422), turning a team bot with tools public
  without clearing them first (422), unknown body fields (422), a `visitorId` shorter than 20 characters,
  more than 5 attachments per conversation, a slug already taken (409).
- Whatever is taught to a public bot is readable by any visitor. Never add private material to one.

## Rules that must hold

- A public bot never gets tools: `converse` passes `allowedTools: []` unless the bot is a team bot with a
  `toolset` (`chat.service.ts`; `tests/unit/kon-chat-routes.test.ts`, "gets no tools at all").
- A bot's tools are the intersection of its agent's `allowedTools` and its group; the kon never widens them.
- A visitor is stored only as the SHA-256 of `visitorId` (`chat.operations.ts`; `tests/unit/kon-chat.test.ts`).
- A conversation is used only by its speaker (`speakersConversation` in `chat.service.ts`), also for
  regenerate, fork, attach and rate (`tests/unit/kon-chat-routes.test.ts`).
- Limits are checked before the engine is called, and a refused turn is not counted.
- Visitors get `reply` and source titles only: no parts, tools, cost or internal ids (`forVisitor`).
- Widget text from the server is set with `textContent`, never as HTML (`tests/unit/kon-chat.test.ts`).
- Row security: conversations and messages are written only by the system, after the route authorizes.
- No `Promise.all` over the request transaction; turns run with `asSystem` after authorization.

## Changing it

- New migration: next number in `migrations/` (`0003_...sql`). Never edit an applied one. This kon has no
  `migrations/history.json`; create one only if a checksum of an applied file must change.
- New file at the root: run `pnpm kon:sync` (it updates `package.json` `files` and `kon.json`).
- Behaviour change: bump `version` in `package.json` and run `pnpm kon:sync`, which copies it to `kon.json`.
- Admin view: edit `admin-src/`, then `pnpm build:admin kon-chat` and commit the rebuilt
  `admin/chat-admin.js`; `pnpm check:admin` checks it. To refresh tallao components, change tallao and run
  `pnpm sync:tallao kon-chat`.
- Operation ids are contract (MCP tool names, fine scopes); do not rename them.
