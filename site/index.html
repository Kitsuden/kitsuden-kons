Add a blog, a CRM or payments with one command.

Kons are optional modules for Kitsuden, the backend for apps that AI agents use. Each kon brings its tables, API routes, MCP tools and permissions. Install the ones you need; the rest never touch your project.

01 One command

What one command does

It copies the kon, installs it and runs its migrations. After a restart your backend has the feature.

In your Kitsuden folder
  1. $ pnpm kitsuden kon add blog --from ../kitsuden-kons
  2. copied to packages/kons/kon-blog
  3. dependencies installed
  4. migrations applied
  5. restart the API

02 After the restart

What your backend has now

  • Tablesits own tables, with row security
  • REST APIits routes, documented in OpenAPI
  • MCP toolsits operations, as tools at /api/mcp
  • Permissionsits own scopes, so each agent key gets only what you grant
  • Panelviews for setup and oversight, when the kon has them

        Install one

        You need a Kitsuden project first (install Kitsuden). Then clone this repository next to it and add the kon.

        Paste this into Claude Code, Cursor or Codex, in your Kitsuden folder. Change blog for the kon you want.

        Add the blog kon to this Kitsuden project.

1. Clone https://github.com/Kitsuden/kitsuden-kons next to this folder.
2. Build the CLI if it isn't built (pnpm --filter @kitsuden/cli build), then
   run: pnpm kitsuden kon add blog --from ../kitsuden-kons
   It shows the source and the commit and asks whether to trust them:
   show me that and wait for my answer.
3. Restart the API. If the kon isn't on by default, tell me to switch it on
   in the panel under Kons.
4. Read kons/kon-blog/AGENTS.md in the kons repository for its scopes and
   MCP tools before you call it. Never invent routes or scopes.

        From your Kitsuden folder. The CLI isn't on npm yet, so it runs from the repository.

        git clone https://github.com/Kitsuden/kitsuden-kons.git ../kitsuden-kons
pnpm --filter @kitsuden/cli build
pnpm kitsuden kon list --available --from ../kitsuden-kons
pnpm kitsuden kon add blog --from ../kitsuden-kons

        The API image installs the kons you list when it builds. The build stops if one of them needs a kon that isn't in the list.

        services:
  kitsuden_api:
    build:
      additional_contexts:
        kons: ../kitsuden-kons
      args:
        KITSUDEN_KONS: "blog,wiki,comments"

        You're installing code. A kon from git is unsigned: the installer shows the source and the commit and asks before it copies anything. Read what you install, the same as any dependency.

        Write your own kon

        One generator writes the manifest, a model, its access policy, a migration with row security, a test and the docs. You fill in the fields. 

        kitsuden make kon recipes
kitsuden make model recipe --kon recipes
pnpm kon:sync
pnpm test
        Your coding agent already knows the rules
        The repository ships an AGENTS.md for the whole repo and one per kon, plus step-by-step skills for a new kon, a fix and the release check.
        Guards catch what reviews miss
        Tests check every kon: a valid manifest, tables created only by its own migrations, docs that match its routes, and a declared maturity.

        Questions people ask first

        Do I need all 30?

        No. Kitsuden's core is a complete backend by itself. Install only the kons whose feature you want; the others are never copied into your project.

        What happens to my data if I remove a kon?

        Its tables and data stay in the database. Removing a kon takes its code out of the project; nothing is dropped.

        Can an agent use a kon straight away?

        Yes, within its key. A kon's operations become MCP tools and REST routes with their own scopes, so an agent only sees the ones its key allows.

        Do kons come with screens?

        Some add views to the admin panel, for setup and oversight. A kon is backend: the app your users see is yours to build on its API.
